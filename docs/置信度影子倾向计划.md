## 一、目标与边界

**要解决的问题**：2026-11 改版后，报告里没有任何东西能表达「这场我更有把握」。登记表 89 条假设都没到「已验证」，信号强度恒为「无」。

**做法**：每份报告多写一行「影子倾向」——不管第 7 节结论是不是「无倾向」，都强制在**亚盘主线**两侧里选一边，并给一个 50~100 的置信度。这一行只记录，用来攒样本检验「模型的把握到底有没有预测力」。

**本计划只做影子期**，硬性边界如下，任何一步都不得越过：

| 不许动 | 说明 |
|--------|------|
| 第 7 节各判定 | 没有已验证假设、没有基本面覆盖时仍写「无倾向」 |
| p_最终 | 仍等于 p_市场 |
| 信号强度、数据质量、k、注额 | `kelly_fraction` 一行不改 |
| 选中项 | 影子倾向不得传给 Jev，不参与 `select_decision` 的任何分支 |
| 串关 | 不读影子倾向 |
| 旧「置信度」解析 | `parse_report_confidence` 与旧报告回测表保持原样 |

**不在本计划内**：达标后如何赋权（见第七节，只描述不实现）；复盘报告里对影子倾向的回顾；TG 命令。

## 二、设计

### 2.1 报告里的一行

放在第 7 节「数据质量」行之后、「关键依据」行之前：

```
- **影子倾向**：C01 让球 Arsenal −0.5｜置信度 58 / 100｜依据：主队主场近 5 场 4 胜且对手缺 2 名主力后卫（仅记录，不影响结论与注额）
```

缺亚盘主线时：

```
- **影子倾向**：无（缺亚盘主线）
```

规则：

1. **对象固定为亚盘主线**。只能在代码候选表里「让球主线」的两行中选一个 ID（通常是 C01 / C02）。不得选次线、胜平负、大小球。
2. **必须选边**。第 7 节写「无倾向」时也要写影子倾向，两者不矛盾：前者是按四层规则能不能下结论，后者是模型的整体倾向。
3. **置信度 50~100，只表示「选中这一侧赢盘的把握」**。不含数据质量（已单独有分数），不设盘型封顶，没有加减分规则。
4. **可用依据不设限**：市场层事实、基本面、未验证假设、模型自己的综合判断都可以。这正是要检验的东西。
5. 行首必须是「影子倾向」，「置信度」写在行中间。**不要另起一行写「置信度：XX」**——那是旧格式，会被旧解析器当成旧尺子的分数。

### 2.2 打分锚点（写进提示词，防止全部挤在 60~70）

| 分数 | 含义 |
|------|------|
| 50 | 抛硬币，看不出任何一侧更好。**这是最常见的正常答案，不要为了显得有判断而抬高** |
| 55 | 略偏一侧，只有一条弱理由 |
| 60 | 有一条明确理由 |
| 65 | 两条相互独立的理由同向 |
| 70 | 三条以上独立理由同向，且没有反向理由 |
| 80+ | 罕见；须写明为什么市场价格没有反映这些信息 |

### 2.3 数据落在哪里

只落一处：第 8 节的 `<!-- decision_final {json} -->`。新增键（只增不改，schema 仍为 `decision_final/1`）：

```json
"lean": {"id": "C01", "play": "让球 Arsenal -0.5", "odds": 1.93, "conf": 58},
"writer_model": "gpt-6-astra-cpa"
```

- 影子倾向缺失或不合法 → 不写 `lean` 键。
- 取不到模型名 → 不写 `writer_model` 键。
- 回测脚本只读 `decision_final`，不再另外解析报告正文。

**必须记模型名**：不同模型的打分尺度不同，统计要能按模型拆开；换主力模型后校准要重算。

### 2.4 检验方式（预登记，写进规则文件）

分两段，避免「先看数据再挑切法」：

**定线期**：前 60 场已结算样本。只看置信度的分布，不看命中率做决定。脚本给出建议线 T = 使约 30% 样本落在 T 及以上的分数（取 5 的倍数，下限 60）。由用户确认 T 和起算日期，写进规则文件，之后不改。

**检验期**：起算日期之后的样本。只检验一条：

> **H-CONF01**：影子倾向置信度 ≥ T 时，按首要分析庄赔率下注亚盘主线该侧，ROI > 0。

| 结论 | 条件（与假设升降级标准一致） |
|------|------------------------------|
| 达标 | ≥T 组 ≥100 场，ROI > 0，前后两半 ROI 同号，去掉盈利最大一笔后仍 > 0 |
| 否决 | ≥T 组 ≥60 场，且方向命中率的 95% 区间上限 < 50% |
| 继续观察 | 其余情况 |

- 不拟合映射表，不事后换分桶。分桶表只作描述。
- 换主力模型：新模型的样本单独计数，重新走定线期。
- 按每天 4~6 场估算：定线期约 2 周，检验期攒够 100 场 ≥T 样本约需 2~3 个月。

### 步骤 3：`bot/typesafe_decisions.py`

**3a. 解析**。在 `parse_data_quality` 之后新增：

```python
@dataclass(frozen=True, slots=True)
class ShadowLean:
    candidate_id: str      # 归一后的 C01..Cn
    play: str
    odds: float
    conf: int              # 50~100


_SHADOW_LEAN_LINE_RE = re.compile(r"(?m)^[ \t]*[-*]?[ \t]*\**影子倾向\**[ \t]*[：:].*(?:\r?\n)?")


def strip_shadow_lean(text: str) -> str:
    """去掉「影子倾向」行。凡是把报告交给会做选择的模型（Jev、串关抽取）之前都要先剥掉，
    保证影子倾向不影响任何下注决定。"""
    return _SHADOW_LEAN_LINE_RE.sub("", text or "")


def parse_shadow_lean(report: str, candidates) -> ShadowLean | None:
    """第 7 节「影子倾向：C01 …｜置信度 58 / 100」→ ShadowLean。
    只接受候选表里最靠前的两条让球行（主线两侧）；写「无」、缺行、ID 越界、
    置信度不在 [SHADOW_LEAN_CONF_MIN, SHADOW_LEAN_CONF_MAX] 时返回 None。"""
```

实现要点：

- 用 `extract_conclusion_section` 取第 7 节，`_plain` 后用 `(?m)^\s*[-*]?\s*影子倾向\s*[：:]\s*(.*)$` 取行。
- ID：行内第一个 `C\d{1,2}`，补零成 `C01` 形式。
- 置信度：行内 `置信度\s*[：:]?\s*(\d{1,3})`。
- 合法 ID 集合：`candidates` 中 `play` 以「让球」开头的**前两条**的 `candidate_id`。`candidates` 传 `_selection_pool(report)` 返回的那一套，保证与定稿用的是同一套 ID。先读 `_selection_pool` 和 `DecisionCandidate` 的定义，确认字段名。
- 候选的 `odds` 为空或 ≤1 → 返回 `None`。

**3b. 不让 Jev 看到**。找到 `_request_selection`（被 `select_decision` 约 1252 行调用）以及它往下组装 Jev 输入的地方，凡是取报告第 7 节或全文作为输入之处，先过一遍 `strip_shadow_lean`。同文件里 `log_selection_shadow` 以及约 1650~1810 行其它调用 TypeSafe 的路径同样处理。做完后全文件搜 `extract_conclusion_section(`，逐个确认：用于**喂给模型**的都剥了，用于**解析字段**的不要剥。

**3c. 写入 `decision_final`**。

- `DecisionSelection` 加两个字段（放在 `focus_note` 之后，带默认值）：`lean: ShadowLean | None = None`、`writer_model: str = ""`。
- `select_decision` 加关键字参数 `writer_model: str = ""`。在算出 `candidates` 之后：`lean = parse_shadow_lean(report, candidates) if config.SHADOW_LEAN_MODE == "on" else None`，把 `lean` 和 `writer_model` 放进 `common` 字典。**除此之外 `select_decision` 的任何分支不得读取 `lean`。**
- `_selection_block` 的 `payload`（约 1421 行），在 `focus` 那段之后加：


只统计赛前报告：路径以 `_report.md` 结尾的文件（现有 `cmd_extract` 已按此过滤）。实现前确认复盘报告的归档文件名不以 `_report.md` 结尾；如果会混进来，在 `extract_one` 里按文件名或标题排除，并在输出里注明排除了多少份。

输出 `scripts/output/backtest/lean.md`，内容按顺序：

1. **样本概况**：有影子倾向的报告数、配到比分的场数、缺行/不合法的份数。
2. **按模型**：每个 `writer_model` 的场数、置信度均值与中位数。
3. **置信度分布**：按 50–54 / 55–59 / 60–64 / 65–69 / 70–74 / 75+ 的场数与占比。

## 七、达标之后（本计划不实现，留作记录）

只有 H-CONF01 按第 2.4 节达标后才讨论赋权，届时另写计划。倾向的方案：

- 把 H-CONF01 登记进 `rules/假设登记表.md`，状态「已验证」，走已有通道：信号强度「中」→ 基础 k 1/4 → 按登记命中率做 log-odds 平移。不新建置信度系数表。
- 只对亚盘主线、只对检验通过的那个模型生效。
- 被否决则删除影子倾向行，结论记入 `reference_staking_kelly.md` 7.4。

不采用的做法及原因：

- **只调 k 不调概率**：p_最终 = p_市场 时正 edge 只来自首要庄报价偏离多庄平均，与方向把握无关；调 k 放大的是价格偏差注，不是有把握的方向。
- **负 ROI 桶降为探索注**：p 等于市场价时每个桶扣掉抽水后期望都为负，这条规则会对所有桶触发。
- **拟合多桶映射表**：桶多样本少，总会有一个桶碰巧达标。
