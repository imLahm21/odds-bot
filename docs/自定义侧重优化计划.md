## 0. 背景与目标

`/analyze` 有两条路：预设精算（不带侧重）和「✍️ 自定义侧重」（用户补一句话）。
用户反馈自定义侧重引导效果弱。原因已查明：

1. 侧重文字接在约 14 万字规则之后（`analyzer._analyze_prompts` 的 `===== 用户额外侧重 =====`），后面还有 10 多万字数据，被埋在中间。
2. 报告格式固定第 1~8 节，没有必须回应侧重的位置。
3. 新分层后方向、概率、选注都由规则和代码决定，一句话改不动。
4. 侧重对代码层没有任何作用。

用户实际常用的侧重只有四种，外加偶尔的补充信息：

| 模式 key | 按钮文字 | 用户原话 |
|---|---|---|
| `ou` | 📊 大小球 | 重点关注大小球 |
| `score` | 🎯 波胆 | 重点关注波胆（正确比分） |
| `aggressive` | 🔥 激进 | 激进倾向 |
| `conservative` | 🛡 保守 | 保守倾向 |

**目标**：这四种模式由代码确定性执行；自由文字放到输入末尾并强制在报告新增的第 9 节回应。

**已定的决定（不要改）**

- 用户提供的信息（伤停、首发、战意等）**允许参与基本面覆盖判断**，但报告必须标注「用户提供·未核实」。
- 任何模式都**不能改变方向判定规则**：方向仍只来自「已验证」假设或基本面明文覆盖。
- 数据质量 <40 时一律空仓，任何模式都不例外。
- 预设精算（不带侧重）的提示词、报告和决策结果必须与改动前**完全一致**。

## 1. 各模式的确切行为

### 1.1 `ou` 大小球重点

- 提示词：第 9 节按「大小球专题」模板写（见 3.3）。
- 代码注入：`### 总进球分布（代码计算）` 段（见 WP-2）。
- 定稿：候选的 `play` 含「大小球」视为大小球候选（覆盖 `大小球 大 2.5`、`主队大小球…`、`客队大小球…`）。
  - 价值注档：正 edge 候选里**有**大小球候选 → 只在大小球候选里选（Jev 的候选集也只给这些）；**没有** → 按常规流程选，并在决策段注明。
  - 探索注档：达到探索下限的候选里有大小球候选 → 取其中 edge 最高的；没有 → 按常规。

### 1.2 `score` 波胆重点

- 代码注入：`### 比分概率表（代码计算）` 段（见 WP-2）：概率最高的 8 个比分，每行给概率和公平赔率（`1/概率`）。
- 提示词：第 9 节按「波胆专题」模板写，照抄该表，并给出 2~3 个首选比分。
- 定稿：**不影响**。库里没有波胆盘口报价，算不出 edge，波胆不进候选表、不由代码选定。第 9 节固定写一句：
  `波胆无市场报价，以下为模型公平赔率；BCG 报价 ≥ 公平赔率 × 1.15 才有价值。`
- 进球模型不可用（`goals_model.states_from_csv` 返回 `None`）时，该段写「大小球盘口缺失，无法给出比分概率」，第 9 节照实说明，不编造。

### 1.3 `aggressive` 激进

- 定稿：价值注的 `k = min(原 k × FOCUS_AGGRESSIVE_K_MULT, FOCUS_K_MAX)`。单注上限 `PARLAY_STAKE_CAP` 不变。探索注不变。
- 提示词：只在第 9 节说明「激进口径：凯利分数 ×2（上限 1/2），方向与候选不变」。

### 1.4 `conservative` 保守

- 定稿：价值注的 `k = 原 k × FOCUS_CONSERVATIVE_K_MULT`；**不下探索注**（等同 `explore_allowed=False`）。
- 提示词：只在第 9 节说明「保守口径：凯利分数减半，不下探索注」。

### 1.5 组合规则

- `ou` 与 `score` 可同时选。
- `aggressive` 与 `conservative` 互斥：按钮上后选的覆盖先选的；文字里两个关键词同时出现时两个都不生效，并在第 9 节注明「激进与保守同时出现，按常规口径」。
- 自由文字可与任意模式并存。

### WP-1 新模块 `bot/focus.py`

侧重全程仍用现有的 `extra_instruction: str` 传递，**不改任何函数签名里的这个参数**。模式用前缀标记编码进字符串：

```
[[focus:ou,conservative]] 主队主力前锋确认缺阵
```

实现以下内容（纯函数，无 IO，无 LLM）：

    conflict: bool = False      # 文字里同时出现激进与保守

    @property
    def empty(self) -> bool: ...          # 无模式且无文字

def encode(modes, text: str = "") -> str
    # 无模式时原样返回 text.strip()；有模式时返回 "[[focus:a,b]] text"
def parse(extra_instruction: str) -> Focus

    # 2) 对自由文字按 keywords 检测，并入模式
    # 3) 激进与保守都在：若都来自文字 → 两个都去掉且 conflict=True；
    #    若一个来自标记一个来自文字 → 保留标记里的那个
def label(focus: Focus) -> str
    # 例："📊 大小球 + 🛡 保守；补充：主队主力前锋确认缺阵"；空侧重返回 ""

def stamp(report: str, focus: Focus) -> str
    # 在报告的「## 赛事：」那一行之后插入一行 "> 本场侧重：{label}"；
    # 找不到该行就插在最前面；focus.empty 或已存在该行时原样返回

### WP-2 代码计算的两个注入段（`bot/goals_model.py`）

新增两个函数，输入都是 `states_from_csv(csv_text)` 的返回值 `st`：

```python
def format_score_block(st: dict | None, top_n: int, margin: float) -> str
def format_total_goals_block(st: dict | None) -> str
```

- 用 `score_matrix(st["lambda_home"], st["lambda_away"])` 重建比分矩阵。
- `format_score_block`：标题 `### 比分概率表（代码计算）`；表头 `| 比分 | 概率 | 公平赔率 | 有价值的报价下限 |`；
  取概率最高的 `top_n` 个比分（主:客），公平赔率 = `1/概率` 保留 2 位，下限 = 公平赔率 × `(1+margin)`；
  表后一行写这 `top_n` 个比分的合计概率；最后附一句「模型估计，非观测频率；无市场报价，不计 edge」。
- `format_total_goals_block`：标题 `### 总进球分布（代码计算）`；一行列出 `0球 / 1球 / 2球 / 3球 / 4球 / 5球+` 的概率；
  再给 `P(≤2)`、`P(≥3)` 两个数；最后附一句「大小球方向仍以市场去抽水概率为准」。
- `st` 为 `None` 时两个函数都返回对应标题加一句「大小球盘口缺失，无法计算」。

#### 3.3 各模式写进第 9 节的模板行

- `ou`：
  ```

    两队近况的进失球（引用事实表）；第 8 节各大小球候选的 edge 排序；结论 [大 / 小 / 无倾向] 及理由

- `score`：
  ```
  - **波胆专题**：照抄「比分概率表」；给出 2~3 个首选比分及理由（须与大小球、胜平负判定不矛盾）；
    固定写「波胆无市场报价，以下为模型公平赔率；BCG 报价 ≥ 表中下限才有价值」

- `conflict`：`- **口径**：激进与保守同时出现，按常规口径`
- 有自由文字：
  ```

  ```
